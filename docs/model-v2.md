# モデルv2：家族・現在年・地域・出典・読み込み

ユーザーが了承した推奨方針に基づく実装。構造整理だけだった前段階と異なり、家族の寿命・年代をまたぐイベント・国別の出生先・死亡率が意図的に変わる。

## 採用した仕様

| 項目 | 実装 |
| --- | --- |
| 出生時の記録 | `era`、`region`、`socialClass`、`birthYear`、`birthPlace`、`birthCountry` を保持する |
| 現在の環境 | `environment` を現在年と現在の居所で更新。現在の時代、対応する国・地域のプロファイル、現在の階級区分を別に持つ |
| 国・地域の継承 | 現在の国の対応プロファイルが1つある場合に更新する。出生国は固定し、明示的な移動で現在の国が変わっても出生記録は書き換えない。別の国の表で穴埋めしない。資料がない場合は出生時の地域推定値を保ち、画面にその旨を表示する |
| 現在の身分 | 出生身分は書き換えない。同じ身分IDが現在の区分に存在しなければ、現在の低所得区分を近似に用いる。自動的な出世抽選はしない |
| イベント | 現在の環境と現在年で照合。古い地域表を据え置いた場合、その時代から外れた地域限定イベントは発生させない |
| 家族 | 続柄のユニオン型、出生年、`unborn / alive / dead`、死亡年で管理。弟妹は出生年まで家族欄に出さない |
| 家族の名前 | 個人名・姓・出生姓を分離し、親子の継承と婚姻時の扱いを区別。日本の公称名字・氏の切替、出生名の保存を含む。範囲・出典は [家族の命名モデル](./family-names.md) を参照 |
| 配偶者の年齢 | 同年齢を簡略モデルとして採用。結婚した年に突然20歳として扱う処理を削除 |
| 家族の死亡判定 | 全続柄に、直前の完了した1年間の開始時点の年齢に対応する生命表を適用。出生後最初の完了年は乳児ハザード。子も成人後まで死亡判定を続ける |
| 結婚・本人の子の出産 | 従来どおり、保留中の `isLifecycle` 決断の選択肢を通す。家族の年次処理が自動で結婚や本人の子の出生を発生させることはない |
| 待機期間・子ども上限 | `lifecycleKind`、`cooldownYears`、`maxChildren` で明示。`childbirth_` という命名規則で判断しない |
| 訃報の選択記録 | 選択肢の `recordType: 'loss'` で明示。選択肢IDを変更しても記録種別が変わらない |

現在年の更新は、まず既存の6時代区分と国の対応関係を使う。各国のすべての政権交代・法制度・地方差を年次データ化したものではない。出生地名の変更は江戸→東京などの明示した対応だけで行い、別の国・都市への移住を勝手に発生させない。

## 53地域から97地域へ

欧州、北米、南アジア、東南アジア、サハラ以南、中東・北アフリカ、中南米、旧ソ連、中世イスラム世界を、主に国・歴史的地域の単位へ分割した。定義は `data/regions/national/*.ts`。

出生ウェイトは旧地域の合計を維持する暫定配分。人口の少ない国を含めた世界の全国家を網羅した出生統計ではない。統計を継承した箇所を、独立に確認した国別統計として表示しない。各国の人名リストは仕様の各10件以上を満たす表記例で、24件という件数のために他文化の名前を混ぜない。

窓税とフランスの塩税は別イベントに分けた。窓税は1696年以降のブリテン、塩税は旧制度下のパリに限定する。根拠：[英国議会の窓税解説](https://www.parliament.uk/about/living-heritage/transformingsociety/private-lives/taxation/overview/taxes18thcentury/)、[フランス税関の歴史](https://www.douane.gouv.fr/la-douane/qui-sommes-nous/histoire-de-la-douane-francaise)。

黄色いベスト運動、ベルリンの壁、米国の雇用主医療保険の喪失、カトリーナ、ブラジルのファヴェーラ、メキシコのカルテル、ロシアの徴兵・民営化などを、国・都市・既存の記述が示す年代へ限定した。旧地域IDはデータ移行と継承元の参照用に型へ残すが、出生抽選にはその国別の子プロファイルを登録する。

## 統計と出典

`RegionProfile.statistics` は出生配分、乳児・5歳未満死亡率、15歳時の寿命、識字、都市化、所得などについて、次を持つ。

- `status`: `estimated`（推定）、`inherited`（別範囲・年の値を継承）、`sourced`（対応する出典・年の値）。
- `period`: 参照期間。
- `sourceIds`: `statisticSources.ts` に登録した出典。
- `note`: 適用範囲と仮定。
- `inheritedFrom`: 国別の独立値ではなく親プロファイルから継承した場合の参照。

### 取り込んだ年次死亡率

World Bank WDI APIから、UN IGMEによる乳児死亡率 `SP.DYN.IMRT.IN` と5歳未満死亡率 `SH.DYN.MORT` を取得。1960〜2024年の範囲内で両方の値が利用できる **41か国、2,576か国年** を `annualMortality.json` に同梱した。取得記録は2026年11月1日。

- [乳児死亡率の定義・出典・利用条件](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/SP.DYN.IMRT.IN)
- [5歳未満死亡率の定義・出典](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/SH.DYN.MORT)
- [World Bankデータ利用条件](https://www.worldbank.org/en/about/legal/terms-of-use-for-datasets)

ゲーム中にAPIへ問い合わせない。年次表は現代の時代データを必要とする人生で読み込む。

同じ国・年の値がある場合はその推計を適用する。最初のデータ年より前を後年の値で埋めない。最後のデータ年以降は最終年の値を据え置き、`inherited` と「将来の観測値ではない」という注記を付ける。資料にない国を隣国の値で埋めない。値を低くするためのキャップや補正は追加していない。

**成人余命・出生配分・識字・所得などの多くは、引き続き既存モデルの推定値。** 出生時平均寿命を15歳時平均余命へ置き換える操作はしていない。成人ハザードは、現在の対応地域の `lifeExpectancyAt15` を使う既存Gompertzモデルのまま。`UN WPP 2024` は今後の整備に使える参考資料として登録したが、[1950年以降を対象とする同資料](https://population.un.org/wpp/)を古代・中世の数値の出典としては扱わない。

更新する場合：

```sh
python3 scripts/update-mortality.py --as-of YYYY-MM-DD
```

この操作は外部データの更新なので、差分・出典・新旧値と回帰テストを確認してから採用する。

## 時代別読み込み

`SessionController` は同期の全データエンジンをインポートしない。`loadSimulation.ts` が、軽量な時代ウェイトから出生時代だけを抽選し、必要な地域・イベント・世界史を読み込んだ後に人物を生成する。

現在の時代区分は最短でも145年で上限寿命110年より長いため、生涯にまたぎ得る次の1時代も先読みする。複数時代を対象にする共通イベントは対応するモジュールをロードする。たとえば古典期モジュール内の神判が中世にも適用されるため、ファイル名だけで対象時代を決めず、その依存も読み込む。

年次進行・早送りは開始後も同期処理。途中のイベント抽選中に通信待ちを挟まない。読み込み中は出生ボタンの二重実行と時間進行を防ぎ、取消後に古い読み込みが完了しても人物を復活させない。読み込み失敗はタイトル上に表示し、ブラウザの失敗したモジュールキャッシュを避けるため、再読み込みしてやり直す操作を用意した。

`engine.ts` はテスト・データ検査向けの全件読み込み互換API。ブラウザは `simulation.ts` / `core.ts` にデータを渡して実行する。両経路の人生・決断・乱数消費が一致するテストを持つ。

## 検証と変更の扱い

- 3,000人生シミュレーションと既存の乳児・5歳未満ハザード、保存、地域隔離を維持。
- イベントの改名で待機期間・子ども上限・訃報種別が変わらないこと。
- 未出生の弟妹、乳児期の初年度、成人した子、同年齢の配偶者。
- 出生記録を保持したままの時代更新と、資料欠落時に他国へ切り替えないこと。
- 統計出典・期間、年次表の整合性、未来値の注記。
- 全件／時代別カタログの24人生の一致。
- 非同期読み込みの二重実行防止・取消・失敗・再試行。
- デスクトップ／モバイルの出生・決断・死亡・テーマ・読み込み失敗からの復帰。

旧フィクスチャ `life-traces.json` は構造リファクタリング前の参照として保持。モデルv2は家族・地域・死亡率を意図的に変更したため、その古いハッシュとの一致を要求しない。新しい規則の検証と、`life-traces-v2.json` による回帰検証を行う。期待値の更新は、モデルやデータの差をレビューしてから明示的に実行する。

```sh
bun scripts/update-life-traces.ts --accept-model-v2
```

残る作業は、国・年代ごとの資料を増やして推定・継承値を置き換えること、同じ国の中の文化・宗教・階層や、時代区分より細かな制度変更を追加すること。今回の実装で歴史資料の欠落まで解消したとは扱わない。

## 検証結果

- `bun run check`：エラー・警告0。
- `bun test`：90件成功（3,000人生・命名規則の16件を含む）。
- `bun run test:e2e`：12件成功（デスクトップ・モバイル、家族の姓の表示、読み込み失敗からの復帰を含む）。
- `bun run build`：成功。最大クライアントJSチャンクは約91.81 kB。前段階の約584 kBから分割され、500 kB超の警告は解消。これは最大チャンクの比較であり、初期読み込み総量の比較ではない。
